高分辨率设备使用低倍图会导致图像模糊，影响用户体验

举例：
使用min-device-pixel-ratio参数检测设备DPI
阈值设定：当比值达到2时使用@2x图片，达到3时使用@3x图片
实际应用：通过@media only screen and (-webkit-min-device-pixel-ratio: 2)实现条件判断

resolution

resolution（在 Web 语境里通常指 device-pixel-ratio，即 1x/2x/3x）替代的是“手工写 JS 或媒体查询去判断屏幕密度、再动态换图”的麻烦做法。
一句话：以前靠脚本，现在靠浏览器原生机制。
过去没有 srcset 时
用 JS 测 window.devicePixelRatio
手动改 <img src> 或者给不同密度屏插不同 <img>
还得自己控制缓存、回退，代码臃肿。
现在有了 srcset + x 描述符
浏览器在 下载前 就根据 当前设备 resolution 选好图，只发一次请求。
不用写任何 JS，也不用写 @media (-webkit-min-device-pixel-ratio: 2) 之类的 CSS。
无分辨率信息的老浏览器直接回退到 src，天然降级。
所以
“resolution 适配”替代的是：手撸 JS、手写媒体查询、多套 <img> 切换——这些又脏又容易漏的“土法炼钢”方案。
